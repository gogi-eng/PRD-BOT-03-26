# Стратегия Hedge Pair (21.08.26) — простыми словами

## Важно сразу

Это **не** схема «всегда в плюсе». Прибыль возможна только если после первого стопа цена **продолжает** идти в сторону тренда до тейк-профита. Гарантии нет.

## Почему «фейковые» 150/120 не работают

Иногда обещают: «открой лонг и шорт, на одном SL, на другом TP больше — всегда плюс».  
На деле:

1. Пока открыты **обе** ноги, движение цены даёт примерно **+X на одной и −X на другой** (почти ноль).
2. Когда одна нога закрывается по SL (убыток L), вторая в этот момент в плюсе примерно на L — это **ещё не зафиксированная** прибыль.
3. Если потом цена **развернётся**, вторая нога тоже может уйти в SL — получите **два убытка**.
4. Биржа берёт **комиссии** (и проскальзывание). Даже «красивая» математика без комиссий на практике минусует.

Цифры вроде 150/120 без модели продолжения тренда и комиссий — это иллюзия, а не edge.

## Почему при TP = SL вы почти всегда в минусе

Если тейк равен стопу по расстоянию:

- одна нога: −SL  
- вторая: +TP (= +SL)  
- **итог до комиссий ≈ 0**  
- после комиссий на две ноги: **≈ −2 × комиссия** → стабильный минус.

Симуляция в коде это подтверждает (`test_symmetric_tp_equals_sl_is_fee_negative`).

## Как ЭТА стратегия может дать плюс

Название: **Trend-Continuation Hedge Pair**.

1. Открываем равный лонг + шорт **только** когда фильтр тренда даёт направление (цена относительно EMA на старшем ТФ).
2. На обеих ногах одинаковый SL = `sl_price_pct` (например 0.8% цены).
3. TP дальше стопа: `tp_price_pct >= sl_price_pct × tp_to_sl_ratio` (по умолчанию ×1.8).
4. Цена уходит против одной ноги → она закрывается по SL (убыток L). Вторую **оставляем**.
5. На оставшейся ноге: перенос SL в безубыток+комиссия после `be_after_profit_pct`, затем трейл `trail_distance_pct`.
6. Цель раннера — дойти до TP. Тогда: **+TP − SL − комиссии**. При TP заметно больше SL и достаточном проценте продолжений — матожидание может быть положительным.
7. Таймаут `max_pair_minutes`: если ничего не закрылось — закрываем обе ноги.

Грубо: нужно, чтобы **вероятность продолжения × (TP/SL)** после комиссий была **больше 1**.

## Когда будет убыток

- Разворот сразу после первого SL (вторая нога тоже в стоп).
- Боковик / «пила» без продолжения.
- Слабый тренд, ложный bias EMA.
- Слишком тесный TP (почти = SL) — комиссии съедают край.
- Переторговля, несколько пар сразу (в конфиге `max_pairs: 1`).

## Когда НЕ включать

- Не понимаете логику «после первого стопа нужен тренд».
- Нет hedge-mode на Bybit / не готовы к двум позициям по одному символу.
- Высокая волатильность новостей, низкая ликвидность.
- Пока не прогнали `scripts/backtest_hedge_pair.py` и тесты локально.
- На реале с `execute: true` без сухого прогона на testnet / малых суммах.

## Как включить на сервере (осторожно)

В `deploy/config.production.yaml` (или вашем `config.yaml`):

```yaml
hedge_pair:
  enabled: false    # сначала false
  execute: false    # даже при enabled — только лог «would open»
  ...
```

1. Оставьте `enabled: false` / `execute: false` — код и симуляция есть, ордера не шлёт.
2. Прочитайте этот файл и результаты бэктеста.
3. На тестовом контуре: `enabled: true`, `execute: false` — смотрите логи `hedge_pair would open`.
4. Только после этого и малых маржей: `execute: true` (нужен hedge mode Bybit, `position_idx` 1/2).

Параметры по умолчанию рассчитаны на **малую** маржу на ногу (`margin_pct_per_leg: 2.0`), плечо 5, одна пара.

## Честные ожидания

| Сценарий | Ожидаемый итог |
|----------|----------------|
| TP = SL | Минус на комиссиях |
| Продолжение тренда до TP | Плюс порядка TP−SL−комиссии |
| Разворот после первого SL | Минус (часто около −2×SL−комиссии) |
| Таймаут / боковик | Около нуля или небольшой минус |

Стратегия **не заменяет** риск-менеджмент. Цель — реалистичный edge при продолжении тренда, а не «вечный профит».

Проверка у себя:

```text

py -3 scripts/backtest_hedge_pair.py
```
