# Стратегия Hedge Pair (21.08.26) — понятным языком

## Важно

Это **не** схема «всегда в плюсе». Прибыль возможна только когда цена **продолжает** идти в сторону bias после первого стопа противоположной ноги. Гарантий нет.

## Почему «симметрия» 150/120 не работает

При одинаковых ногах: лонг + шорт, один стоп SL, другой берёт TP того же размера — чистый результат около нуля.  
На деле:

1. Пока открыты **обе** ноги, движение цены даёт примерно **+X на одной и −X на другой** (почти ноль).
2. Когда одна нога закрывается по SL (обычно L), остаётся runner в сторону продолжения — это **единственный сценарий возможной** прибыли.
3. Если потом цена **разворачивается**, runner тоже может дойти до SL — получите **оба убытка**.
4. Всегда берите **комиссии** (и проскальзывание). Даже идеальный матч без комиссии не спасёт от fees.

Цифры вроде 150/120 без продолжения тренда и комиссий — иллюзия, не edge.

## Почему при TP = SL вы почти всегда в минусе

Если тейк равен стопу по расстоянию:

- Одна нога: −SL  
- Другая: +TP (= +SL)  
- **Итог до комиссий ≈ 0**  
- После комиссий на обе ноги: **≈ −2 × комиссия** за стабильный исход.

Подтверждено в юнит-тесте (	est_symmetric_tp_equals_sl_is_fee_negative).

## Как эта стратегия может дать плюс

Название: **Trend-Continuation Hedge Pair**.

1. Открываем равный лонг + шорт **только** когда фильтр тренда даёт bias (цена относительно EMA на старшем ТФ).
2. На обе: начальный защитный SL = sl_price_pct (например 0.8% цены).
3. TP дальше стопа: 	p_price_pct >= sl_price_pct × tp_to_sl_ratio (по умолчанию ×1.8).
4. Ждём, пока первая из ног закроется по SL (обычно L). Вторую **оставляем**.
5. На оставшейся ноге: двигаем SL в безубыток после e_after_profit_pct, затем трейл 	rail_distance_pct.
6. Цель runner — дойти до TP. Итог: **+TP − SL − комиссии**. Если TP заметно больше SL и продолжение тренда случается достаточно часто — мат. ожидание может быть положительным.
7. Таймаут max_pair_minutes: если ничего не случилось — закрываем обе ноги.

Важно: нужен, чтобы **отношение продолжения × (TP/SL)** после комиссий было **больше 1**.

## Когда бот убыточен

- Разворот рынка после первого SL (runner тоже в стоп).
- Боковик / whipsaw без продолжения.
- Слабый тренд, ложный bias EMA.
- Близкие тейк/стоп (почти = SL) — комиссии съедают всё.
- Переторговка, несколько пар сразу (в конфиге max_pairs: 1).

## Когда НЕ включать

- Не понимаете логику «первая стоп-нога, потом runner в тренде».
- Нет hedge-mode на Bybit / не готовы к двум позициям по одному символу.
- Высокая волатильность новостей, сильный гэп.
- Ещё не прогнали scripts/backtest_hedge_pair.py и тесты локально.
- Не хотите live: поставьте execute: false или enabled: false.

## Когда бот выбирает hedge pair

Hedge pair включается в **общем** цикле оркестратора, но выбирается **только как fallback**:

- после collect_all (own / TA / telegram / whale / ext) сигналов **пусто**;
- нет открытых позиций, блокирующих max_pairs;
- hedge_pair.enabled: true;
- флаг only_when_no_other_signals: true (по умолчанию) — значит fallback ждёт пустого цикла без «чужих» сигналов (не конкурирует).

Иными словами: **не каждый цикл по расписанию**, а только если в этом цикле нет других сигналов после merge.

### Live-открытие (сейчас)

При execute: true бот **реально открывает** пару на Bybit:

- Long: side Buy, positionIdx=1, со своими SL/TP  
- Short: side Sell, positionIdx=2, со своими SL/TP  
- Размер ноги: margin_pct_per_leg % баланса × leverage / цена  
- Если одна нога не открылась — успешная **сразу закрывается** (rollback), односторонней позиции не оставляем  
- Пока пара открыта, каждый цикл вызывается on_price_tick и действия (close / move_sl / flatten) уходят на биржу  

**Обязательно:** аккаунт в **Bybit Hedge Mode** (Combined / One-Way выключен). Если Bybit ругается на positionIdx, в логе будет ясное сообщение на русском.

При execute: false пишется лог вида hedge_pair FALLBACK (no other signals): would open ... без ордеров.

## Как включить / выключить (осторожно)

В deploy/config.production.yaml (или вашем config.yaml):

`yaml
hedge_pair:
  enabled: true
  execute: true           # live long+short; нужен Hedge Mode
  only_when_no_other_signals: true
  leverage: 5
  margin_pct_per_leg: 2.0
  max_pairs: 1
  ...
`

Отключить торговлю парой:

1. enabled: false — стратегия полностью выключена  
2. или execute: false при enabled: true — только лог «would open», без ордеров  

Параметры по умолчанию рассчитаны на **малый** заход на ногу (margin_pct_per_leg: 2.0), плечо 5, одна пара.

## Частые ожидания

| Ожидание | Реальный итог |
|----------|----------------|
| TP = SL | Минус на комиссиях |
| Продолжение тренда до TP | Плюс примерно TP−SL−комиссии |
| Разворот после первого SL | Минус (часто около −2×SL−комиссии) |
| Таймаут / боковик | Около нуля или небольшой минус |

Стратегия **не заменяет** риск-менеджмент. Плюс — вероятностный edge при продолжении тренда, не «вечный профит».
