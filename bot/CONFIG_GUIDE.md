# ПОДРОБНЫЙ ГАЙД ПО CONFIG.YAML
## Каждый параметр — что делает, как влияет на торговлю

---

## timezone_offset: 3
**Что это:** Смещение часового пояса от UTC (3 = Москва, UTC+3).
**Влияет на:** Логи, время отправки уведомлений, расчёт "дневного" лимита торгов.
- **Увеличить** → логи покажут более позднее время
- **Уменьшить** → логи покажут более раннее время

---

## bybit (настройки биржи)

### testnet: false
**Что это:** Торговать на тестовой (false = реальной) бирже Bybit.
- **true** → торгует "игрушечными" деньгами, для тестов
- **false** → РЕАЛЬНЫЕ деньги, реальные сделки

### category: linear
**Что это:** Тип контракта. `linear` = USDT-маржинальные фьючерсы (самый популярный).
- Менять не нужно, это единственный поддерживаемый тип.

## bot (основные настройки бота)

### candle_interval: "1"
**Что это:** Основной таймфрейм (TF) свечей. "1" = 1 минута.
**Влияет на:** Частота анализа, чувствительность сигналов.
- **"1"** → очень быстрые сигналы, много шума, много ложных срабатываний
- **"5"** → медленнее, но надёжнее сигналы, меньше сделок
- **"15"** → ещё медленнее, ещё надёжнее

### htf_interval: "15"
**Что это:** "Высший таймфрейм" для подтверждения. 15 = 15-минутные свечи.
**Влияет на:** Фильтр направления. Бот смотрит тренд на 15мин для подтверждения сигнала на 1мин.
- **Увеличить (60, 240)** → более строгий фильтр, меньше сделок, но точнее
- **Уменьшить (5)** → слабый фильтр, больше сделок, но больше ложных

### htf_4h_interval: "240"
**Что это:** 4-часовой таймфрейм для глобального тренда. 240 = 4 часа.
**Влияет на:** Определение BULL/BEAR/FLAT на 4H. Бот НЕ торгует против 4H тренда.
- Обычно не меняют. 240 = стандарт.

### cycle_sleep_sec: 60
**Что это:** Пауза между циклами сканирования (секунды). Когда нет открытых позиций.
**Влияет на:** Как часто бот ищет новые сигналы.
- **Уменьшить (15-30)** → чаще ищет, быстрее реагирует, больше нагрузка на API
- **Увеличить (120-300)** → реже ищет, меньше нагрузка, может пропустить сигнал

### scan_interval_sec: 60
**Что это:** Минимальный интервал между полными сканированиями всех символов.
- **Уменьшить** → чаще полное сканирование
- **Увеличить** → реже, экономит API-лимиты

### position_active_sleep_sec: 15
**Что это:** Пауза между циклами КОГДА ЕСТЬ открытые позиции. Бот крутится быстрее для управления.
- **Уменьшить (5-10)** → trailing stop обновляется чаще, быстрее реакция
- **Увеличить (30-60)** → медленнее реакция, экономит API

### klines_limit: 180
**Что это:** Сколько последних свечей загружать для анализа.
- **Увеличить (300)** → больше истории, точнее структурный анализ, медленнее
- **Уменьшить (60)** → быстрее, но меньше контекста

### feature_window: 128
**Что это:** Окно данных для AI-модели (Transformer). 128 последних свечей.
- **Увеличить** → модель видит больше истории
- **Уменьшить** → модель видит меньше, быстрее inference

### liquidation_stream_symbols: 12
**Что это:** Сколько символов анализировать для ликвидационной карты.
- **Увеличить** → больше данных о ликвидациях, но медленнее
- **Уменьшить** → быстрее, но меньше ликвидационных магнитов

### signal_only: true
**Что это:** КЛЮЧЕВОЙ ПЕРЕКЛЮЧАТЕЛЬ.
- **true** → бот НЕ ТОРГУЕТ, только показывает сигналы (безопасный режим для сбора данных)
- **false** → бот ТОРГУЕТ реальными деньгами

### signal_cooldown_sec: 3600
**Что это:** Минимальная пауза (сек) между повторными сигналами на один и тот же символ.
- **Уменьшить (300)** → чаще повторные сигналы по одному символу
- **Увеличить (7200)** → реже, защита от спама сигналов

## trading (параметры торговли)

### leverage: 8
**Что это:** Кредитное плечо. 8 = на каждый $1 вашего баланса вы управляете $8.
- **Увеличить (15-20)** → БОЛЬШЕ риск, БОЛЬШЕ потенциальная прибыль/убыток, ближе к ликвидации
- **Уменьшить (3-5)** → МЕНЬШЕ риск, безопаснее, дальше от ликвидации
- **ВНИМАНИЕ:** С маленьким балансом высокое плечо = быстрая ликвидация!

### margin_total_pct: 8.0
**Что это:** Максимальный % баланса, который можно использовать на ВСЕ позиции одновременно.
- **Увеличить (15-20)** → больше денег в рынке, больше риск
- **Уменьшить (3-5)** → меньше денег в рынке, безопаснее

### risk_per_trade_pct: 0.4
**Что это:** Сколько % баланса рискуем на ОДНУ сделку. 0.4% = на балансе $100 рискуем $0.40.
**ЭТО САМЫЙ ВАЖНЫЙ ПАРАМЕТР для размера позиции!**
- **Увеличить (1.0-2.0)** → крупнее позиции, больше прибыль/убыток за сделку
- **Уменьшить (0.1-0.2)** → мельче позиции, безопаснее, но сложно набрать прибыль
- **Правило:** С маленьким балансом (<$50) ставьте 1.0-2.0%, иначе позиции будут "Position too small"

### max_positions: 2
**Что это:** Максимум одновременно открытых позиций.
- **Увеличить (3-5)** → больше сделок параллельно, больше диверсификация, больше риск
- **Уменьшить (1)** → одна сделка за раз, полный фокус, но можно упустить возможности

### min_position_usdt: 10.0
**Что это:** Минимальный размер позиции в долларах. Если рассчитанная позиция меньше — сделка отменяется.
- **Уменьшить (1.0)** → разрешить мелкие позиции (для маленьких балансов)
- **Увеличить (20-50)** → только крупные позиции

### trailing_stop_pct: 1.0
**Что это:** Базовый процент trailing stop от цены (используется как fallback).
- **Увеличить** → trail дальше от цены, больше "дыхания" для позиции
- **Уменьшить** → trail ближе, быстрее фиксирует прибыль, но может закрыть раньше

### tp_pct: 1.8
**Что это:** Базовый Take Profit в процентах от входа (fallback).
- **Увеличить (3.0)** → ждём больше прибыли, реже закрываем, но можем не дождаться
- **Уменьшить (1.0)** → быстрее фиксируем, чаще закрываем с прибылью, но мелкие профиты

### sl_pct: 1.0
**Что это:** Базовый Stop Loss в процентах (fallback).
- **Увеличить (1.5-2.0)** → шире стоп, реже выбивает шумом, но крупнее убыток при срабатывании
- **Уменьшить (0.5)** → узкий стоп, часто выбивает шумом, но мелкие убытки

### blacklist_symbols: [...]
**Что это:** Символы, которые бот НИКОГДА не будет торговать. Проблемные или неликвидные монеты.
- Добавляйте монеты которые постоянно дают убытки.

## entry (параметры входа в сделку)

### transformer_threshold: 0.54
**Что это:** Минимальная вероятность AI-модели для подтверждения направления. 0.54 = 54%.
- **Увеличить (0.65)** → AI должен быть увереннее, строже фильтр
- **Уменьшить (0.50)** → AI пропускает всё (50% = как монетка), слабый фильтр

### max_liq_distance_pct: 1.30
**Что это:** Максимальное расстояние до ликвидационного магнита (% от цены).
**Влияет на:** Бот входит только если "магнит" (цель цены) близко.
- **Увеличить (2.0)** → разрешить более далёкие цели, больше сигналов
- **Уменьшить (0.5)** → только очень близкие цели, меньше сигналов, но точнее

### min_orderflow_imbalance: 1.10
**Что это:** Минимальный дисбаланс ордерфлоу (покупки vs продажи). 1.10 = покупки на 10% больше продаж.
- **Увеличить (1.30)** → нужен сильный дисбаланс, строже
- **Уменьшить (1.0)** → любой дисбаланс, слабый фильтр

### min_rr_ratio: 3.0
**Что это:** Минимальное соотношение Risk:Reward. 3.0 = потенциальная прибыль в 3 раза больше риска.
**ЭТО КЛЮЧЕВОЙ ПАРАМЕТР СТРАТЕГИИ!**
- **Увеличить (4.0-5.0)** → только сделки с огромным потенциалом, очень мало входов
- **Уменьшить (2.0)** → больше сделок, но ниже качество каждой
- **Правило:** С winrate 30-40% нужен R:R минимум 2.5-3.0 для прибыльности

### min_target_profit_pct: 1.2
**Что это:** Минимальная целевая прибыль (% от входа).
- **Увеличить** → бот хочет больше прибыли с каждой сделки
- **Уменьшить** → бот согласен на мелкие цели

### require_structural_tp: true
**Что это:** Требовать структурную цель (уровень сопротивления/поддержки) для TP.
- **true** → TP на реальном уровне (надёжнее)
- **false** → TP рассчитывается математически (может быть "в воздухе")

### min_stop_distance_pct: 0.8
**Что это:** Минимальное расстояние до SL (% от входа).
- **Увеличить (1.2)** → шире стоп, реже выбивает шумом
- **Уменьшить (0.4)** → узкий стоп, чаще выбивает

### min_stop_atr_mult: 1.6
**Что это:** Минимальный SL в множителях ATR. 1.6 × ATR = минимальная дистанция до стопа.
- **Увеличить (2.0-2.5)** → шире стоп, больше "дыхания", но крупнее убыток при стопе
- **Уменьшить (1.0)** → узкий стоп, меньше убыток, но чаще выбивает

### sl_buffer_atr_mult: 1.0
**Что это:** Дополнительный буфер к SL в ATR. Добавляется к структурному стопу.
- **Увеличить (1.5)** → ещё шире, ещё больше "дыхания"
- **Уменьшить (0.3)** → почти без буфера, стоп впритык

### max_entry_extension_atr: 0.75
**Что это:** Максимально допустимое расстояние от зоны входа (в ATR). Если цена убежала от зоны — вход отменяется.
- **Увеличить (1.5)** → разрешить вход даже если цена далеко от зоны
- **Уменьшить (0.3)** → вход только прямо у зоны (точнее, но реже)

### entry_range_atr_mult: 0.22
**Что это:** Размер "зоны входа" (в ATR). Диапазон цен, в котором вход считается валидным.
- **Увеличить** → шире зона, проще войти
- **Уменьшить** → уже зона, нужна точная цена

### allowed_regimes: ["trend", "breakout", "chop"]
**Что это:** В каких рыночных режимах бот может торговать.
- **["trend", "breakout"]** → только в тренде и при пробоях (безопаснее)
- **["trend", "breakout", "chop"]** → также в боковике (больше сделок, но рискованнее)

### zone_proximity_pct: 0.4
**Что это:** Насколько близко цена должна быть к структурной зоне (% от цены).
- **Увеличить (0.8)** → цена может быть дальше от зоны
- **Уменьшить (0.2)** → только прямо у зоны

### max_spread_pct: 0.08
**Что это:** Максимальный спред (разница bid-ask). Если спред шире — вход отменяется.
- **Увеличить (0.15)** → торговать даже с широким спредом (неликвидные монеты)
- **Уменьшить (0.05)** → только ликвидные монеты с узким спредом

### max_funding_rate: 0.05
**Что это:** Максимальный funding rate. Высокий funding = дорого держать позицию.
- **Увеличить (0.10)** → разрешить высокий funding
- **Уменьшить (0.02)** → только дешёвый funding

### entry_threshold: 0.72
**Что это:** МИНИМАЛЬНЫЙ ОБЩИЙ СКОР для входа. Взвешенная сумма всех факторов.
**САМЫЙ ВАЖНЫЙ ФИЛЬТР ВХОДА!**
- **Увеличить (0.80)** → очень строго, мало сделок, но высокое качество
- **Уменьшить (0.55)** → больше сделок, ниже качество
- **Текущая реальность:** Скоры обычно 0.30-0.65, при 0.72 бот почти не торгует!

### trained_model_enabled: true
**Что это:** Использовать обученную AI-модель (Transformer) для фильтрации.
- **true** → AI помогает фильтровать (рекомендуется)
- **false** → без AI, только технический анализ

### trained_model_min_prob: 0.52
**Что это:** Минимальная вероятность от модели для входа. 0.52 = модель должна быть хоть чуть уверена.
- **Увеличить (0.60-0.70)** → модель должна быть очень уверена, мало сделок
- **Уменьшить (0.0)** → модель пропускает всё (отключена фактически)

### trained_model_blend: 0.30
**Что это:** Вес AI-модели в общем скоре. 0.30 = 30% от финального решения зависит от AI.
- **Увеличить (0.50)** → AI решает половину, если модель хорошая — улучшит результат
- **Уменьшить (0.10)** → AI почти не влияет

### trained_model_weights_path: "transformer_weights.pt"
**Что это:** Путь к файлу с весами обученной модели. Не менять!

### min_liq_depth: 0.0
**Что это:** Минимальная "глубина" ликвидационного магнита. 0.0 = не проверять.
- **Увеличить** → только сильные ликвидационные кластеры

### min_smc_score: 0.70
**Что это:** Минимальный SMC (Smart Money Concept) скор. 0.70 = 70%.
- **Увеличить (0.80)** → только сильные SMC-сетапы
- **Уменьшить (0.50)** → слабые тоже пройдут

### min_volatility_pct: 0.04
**Что это:** Минимальная волатильность символа (% от цены).
- **Увеличить** → только волатильные монеты
- **Уменьшить** → даже тихие монеты

### require_sweep: true
**Что это:** Требовать ликвидационный "свип" (сбор стопов) перед входом.
- **true** → вход только после свипа (классический SMC)
- **false** → вход без свипа (больше сигналов)

### require_4h_trend: true
**Что это:** Требовать совпадение направления с 4-часовым трендом.
- **true** → торгуем только ПО тренду 4H (безопаснее)
- **false** → разрешить контртренд (рискованнее)

### strict_htf_mode: true
**Что это:** Строгий режим HTF — сигнал ОБЯЗАН совпадать с трендом на 15мин И 4H.
- **true** → очень строго, мало сигналов
- **false** → достаточно одного TF

### volatility_floor_enabled: true / volatility_floor_atr_pct: 0.06
**Что это:** Фильтр "мёртвого рынка". Если ATR% < 0.06% — символ пропускается.
- **Увеличить (0.15)** → только активные рынки, меньше символов
- **Уменьшить (0.02)** → даже тихие рынки

## exit (параметры выхода)

### hard_sl_atr_mult: 2.5
**Что это:** Жёсткий аварийный стоп-лосс. 2.5 × ATR от входа.
**Последний рубеж защиты!**
- **Увеличить (3.5)** → дальше аварийный стоп, больше места для манёвра
- **Уменьшить (1.5)** → ближе, чаще срабатывает

### early_exit_bars: 6
**Что это:** Если после 6 баров (свечей) позиция НЕ в прибыли — закрыть.
- **Увеличить (12-15)** → дать больше времени позиции развиться
- **Уменьшить (3)** → быстро закрывать "мёртвые" сделки
- **0** → отключить early exit

### early_exit_min_profit_atr: 0.1
**Что это:** Минимальная прибыль (в ATR) чтобы early exit НЕ закрыл. 0.1 × ATR.
- **Увеличить (0.3)** → нужно больше прибыли чтобы пережить early exit
- **Уменьшить (0.0)** → любая положительная прибыль спасает от закрытия

### trailing_activation_atr: 1.1
**Что это:** После скольки ATR прибыли активируется trailing stop (для бот-позиций).
- **Увеличить (2.0)** → trailing стартует позже, больше место для движения
- **Уменьшить (0.5)** → trailing стартует раньше, быстрее защищает прибыль

### trailing_distance_atr: 1.4
**Что это:** Дистанция trailing stop от лучшей цены (в ATR).
- **Увеличить (2.0)** → trail дальше, больше "дыхания", но можно потерять больше прибыли
- **Уменьшить (0.8)** → trail ближе, быстрее фиксирует, но может закрыть рано

### tp_cap_atr_mult: 10.0
**Что это:** Максимальный TP (потолок) в ATR. Если цена пролетела 10 × ATR — закрыть.
- **Увеличить (15)** → разрешить более длинные движения
- **Уменьшить (5)** → быстрее фиксировать крупную прибыль

### min_profit_before_trail_pct: 0.45
**Что это:** Минимальная прибыль (% от цены) перед активацией trail. Fallback для 1R расчёта.
- **Увеличить (1.0)** → trail только при значительной прибыли
- **Уменьшить (0.2)** → trail быстрее стартует

### sl_buffer_atr_mult: 0.5
