## Ассистент

## Почему «каждый раз перезагружается»

Это **не поломка**. Так устроен скрипт деплоя `server_deploy_branch.sh`, который вы запускаете:

```bash
bash scripts/server_deploy_branch.sh 25.05.26-ALL
```

Он **намеренно** делает по шагам:

| Шаг | Что происходит | Зачем |
|-----|----------------|-------|
| 1 | Резервная копия `.env`, `config.yaml`, сессии Telegram | Не потерять настройки |
| 2 | `git pull` новой ветки | Обновить код |
| 3 | **`rebuild_venv.sh`** — старый `venv` → `venv.bak.ДАТА`, новый `venv` с нуля | Чтобы pip/telethon не ломались после обновления |
| 4 | `systemctl restart` trading_bot + telegram_signal_agent | Подхватить новый код (~10–30 сек простоя) |

Длинный список **`Removing venv.bak...`** — это **`git clean`** удалял старые папки-бэкапы `venv` (тысячи файлов telethon). На работу бота это не влияло, но занимало время и место на диске.

---

## Что изменено (уже на GitHub, `f071d54`)

1. **venv не пересобирается**, если он целый и `requirements-unified.txt` не менялся — будет строка:  
   `venv OK — пересборка пропущена`
2. **Старые `venv.bak.*` удаляются** автоматически (остаётся 1 бэкап).
3. **`git clean` не трогает** `venv.bak.*` — не будет километров `Removing...`

После одного деплоя с новым скриптом следующие обновления **кода** будут быстрее.

## Как обновлять код **без** полной пересборки venv

Если менялся только Python-код (как сейчас), на сервере:

```bash
cd /root/PRD-BOT-ALL
git fetch origin
git reset --hard origin/25.05.26-ALL
sudo systemctl restart trading_bot telegram_signal_agent
```

Без `server_deploy_branch.sh` — **быстрее**, но `.env`/`config.yaml` сами не подстрахуются (у вас они уже на месте).

Полный деплой (с бэкапом) — когда менялись зависимости или venv сломан:

```bash
bash scripts/server_deploy_branch.sh 25.05.26-ALL
```

Принудительно пересобрать venv:

```bash
FORCE_VENV_REBUILD=1 bash scripts/rebuild_venv.sh
sudo systemctl restart trading_bot telegram_signal_agent
```
