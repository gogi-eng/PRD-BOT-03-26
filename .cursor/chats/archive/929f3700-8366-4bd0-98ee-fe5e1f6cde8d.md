## Почему каждая строка в логе дважды

В проекте логирование настроено так: **одно и то же сообщение уходит и в консоль (stderr), и в файл `bot.log`**:

```82:111:c:\Users\Labuh\.vscode\PRD-BOT-NEW\bot\trading_bot_imports.py
def _configure_logging() -> None:
    """Console (systemd/journal) + ``bot.log`` in project root — same lines to both."""
    ...
    if not _has_stderr():
        sh = logging.StreamHandler(sys.stderr)
        ...
        root.addHandler(sh)
    if not _has_bot_log_file():
        fh = logging.FileHandler(log_path, encoding="utf-8")
        ...
        root.addHandler(fh)
```

Если при этом **`tail -f bot.log` показывает дубликаты с одинаковым временем**, возможны варианты:

1. **Два процесса бота** пишут в один файл — проверьте на сервере: `ps aux | grep -E 'python|main.py'` (должен быть один рабочий процесс).
2. **`_configure_logging()` вызвалась дважды** и по ошибке добавилось **два FileHandler** на один файл (реже, но бывает при двойном импорте).
3. Вы смотрите не чистый файл, а **объединённый вывод** (например, скрипт дублирует строки).

Если дубликаты есть **только** когда смотрите и journal, и файл — это нормально для двух разных источников; но **внутри одного** `tail -f bot.log` дубликаты не должны повторяться от одного вызова `logger.info`.

## В чём был «баг»

Дубликаты в **`bot.log`** чаще всего возникают не из‑за двух процессов бота, а из‑за **двойной записи в один и тот же файл**:

1. В коде к корневому логгеру вешаются **`StreamHandler(sys.stderr)`** и **`FileHandler(.../bot.log)`**.
2. Если на сервере в **systemd** (или в скрипте запуска) включено что‑то вроде  
   `StandardOutput=append:/root/PRD-BOT-NEW/bot.log` и  
   `StandardError=append:/root/PRD-BOT-NEW/bot.log`,  
   то **stderr уже открыт на этот же файл**.
3. Тогда каждая строка лога уходит **и через stderr в `bot.log`, и через `FileHandler` в `bot.log`** → в файле **две одинаковые строки**.

Об этом прямо написано в вашем же примере для systemd:

```11:12:c:\Users\Labuh\.vscode\PRD-BOT-NEW\scripts\systemd\trading_bot_scalp_log_append.conf.example
# ВАЖНО: не используйте одновременно с FileHandler на bot.log в коде —
#        строки продублируются. Выберите что-то одно.
```

## Что сделано в коде

В `bot/trading_bot_imports.py` добавлена проверка: **если stderr уже указывает на тот же inode, что и `bot.log`, второй `FileHandler` не добавляется** — остаётся только запись через stderr (один раз в файл). Если запускаете вручную в терминале или journal без перенаправления stderr в `bot.log`, **`FileHandler` по‑прежнему создаётся**, как раньше.

Проверка компиляции прошла успешно.

## Почему он снова поднимается

Сейчас у вас одновременно:

1. **`prd_bot_new.service`** — у сервиса обычно стоит **`Restart=always`**: процесс убили или упал → **systemd снова запускает**.
2. **Cron каждые 2 минуты**: `*/2 * * * * /root/bot_watchdog_new.sh` → внутри вызывается `scripts/bot_watchdog.sh`, который при «бот не живой» делает **`nohup … main.py >> bot.log`** (см. строки 55–56 в репозитории).

Пока **хоть один** из этих механизмов активен, бот будет **возвращаться**.

Дополнительно: в `/root/bot_watchdog_new.sh` задаётся `WATCHDOG_MAIN_ARGS="--trading-bot"`, но **`scripts/bot_watchdog.sh` эту переменную вообще не использует** — всегда запускает просто `main.py`. Для текущего **`PRD-BOT-NEW/main.py`** это даже хорошо: там **нет** разбора `--trading-bot`, лишний аргумент вызвал бы ошибку.

## Как **действительно остановить** PRD-BOT-NEW

Делайте **в таком порядке** (важен порядок из‑за cron раз в 2 минуты):

```bash

crontab -e
# закомментировать строку:
# */2 * * * * /root/bot_watchdog_new.sh

# 2) Остановить systemd

# 3) На всякий случай убить все процессы этого main.py

# 4) Убрать pid-файл (если процессов уже нет)

# 5) Проверка — должно быть пусто

sudo systemctl start prd_bot_new.service   # запустить
sudo systemctl restart prd_bot_new.service # перезапуск
```

Итог: **«не останавливается»** — это не зависание, а **автоподъём** со стороны **systemd и/или watchdog в cron**. Отключите то, чем реально хотите пользоваться (обычно один способ: либо systemd, либо cron+watchdog).
